# Bundles i18n

Os bundles `.properties` são os arquivos de tradução consumidos pelo `TranslatorImpl` via `@sap/textbundle`. Cada arquivo corresponde a um locale; o bundle base (`i18n.properties`) serve como fallback universal.

## Convenção de arquivos

| Arquivo | Propósito | Obrigatório? |
|---|---|---|
| `i18n.properties` | Bundle base (fallback EN) | ✓ Sim |
| `i18n_pt.properties` | Locale PT-BR | Recomendado |
| `i18n_es.properties` | Locale ES | Quando há clientes ES |
| `i18n_en.properties` | Locale EN explícito | Opcional (base já é EN) |

## Formato de chaves

Usar notação `dominio.subdominio.especifico` em `lowerCamelCase` — escolher uma convenção e manter em todo o projeto.

```properties
# i18n.properties (base / EN — fallback)
email.required=Email is required.
email.invalid=Email is invalid.
user.notFound=User not found.
priceList.alreadyApproved=Price list already approved.
```

```properties
# i18n_pt.properties
email.required=Email é obrigatório.
email.invalid=Email inválido.
user.notFound=Usuário não encontrado.
priceList.alreadyApproved=Lista de preços já aprovada.
```

## Placeholders

Usar `{0}`, `{1}`, ... para argumentos posicionais.

```properties
# i18n_pt.properties
priceList.notFound=Lista de preços {0} não encontrada.
```

Uso no código:

```typescript
translator.translate({ text: 'priceList.notFound', args: ['PL-123'] });
// → "Lista de preços PL-123 não encontrada."
```

## Configuração CAP nativo — `.cdsrc.json`

```json
{
    "i18n": {
        "folders": ["src/infrastructure/utils/translator/i18n"]
    }
}
```

Apontar o `.cdsrc.json` para a mesma pasta mantém **um único conjunto de bundles** para duas finalidades:

1. O nosso `TranslatorImpl` (mensagens de erro da aplicação).
2. O CAP internamente (mensagens de erro nativas do framework via `@i18n: '{path}'` em `.cds`).

## Regras

1. **Bundle base (`i18n.properties`) sempre presente** em EN — funciona como fallback quando o locale do request não tem bundle.
2. **Toda chave usada no código tem entrada no bundle base.** Validar via linter ou script de CI (research dedicado futuro).
3. **Sem caracteres especiais escapados manualmente.** O `.properties` aceita UTF-8 direto — escrever `ã`, `ç`, `é` diretamente.
4. **Manter ordem alfabética por chave.** Facilita diff e merge entre branches.
5. **Sufixo do arquivo segue ISO 639-1** com variantes opcionais: `pt`, `pt_BR`, `es`, `es_ES`. O `@sap/textbundle` resolve hierarquicamente (`pt_BR` → `pt` → base).

## Anti-padrões

1. **Bundle único `messages_pt.properties` sem bundle base** (anti-padrão Suzano). Quebra o fallback para outros locales — qualquer chave ausente no `messages_pt` retorna vazia.
2. **Chaves com typo de locale** (`en_En`, `pt_br`) — usar exatamente os sufixos que o `@sap/textbundle` espera.
3. **Texto traduzido inline no código** (`throw new Error('Email é obrigatório.')`) em vez de chave (`new BadRequestError('email.required')`). Impede internacionalização e dificulta rastreamento.
4. **Chaves duplicadas com variantes** (`emailRequired` em um bundle e `email.required` em outro) — manter uma única chave canônica por mensagem.
