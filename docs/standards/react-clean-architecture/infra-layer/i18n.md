# Infra layer — i18n (Internacionalização)

O sistema de internacionalização usa **i18next** com detecção automática de idioma do navegador. Suporta português (pt-BR) e inglês (en), com pt-BR como fallback. A função `translate()` é o ponto de acesso centralizado em todo o código.

## Estrutura

```
src/infra/i18n/
├── index.ts       → inicialização do i18next + export translate()
├── pt-br.json     → traduções em português do Brasil
└── en.json        → traduções em inglês
```

## `index.ts` — inicialização e export da função `translate`

```typescript
// src/infra/i18n/index.ts

import i18n from 'i18next';
import LanguageDetector from 'i18next-browser-languagedetector';
import { initReactI18next } from 'react-i18next';

import en from '@/infra/i18n/en.json';
import ptBR from '@/infra/i18n/pt-br.json';

i18n
    .use(LanguageDetector)
    .use(initReactI18next)
    .init({
        resources: {
            'pt-BR': { translation: ptBR },
            'en': { translation: en }
        },
        fallbackLng: 'pt-BR',
        interpolation: { escapeValue: false }
    });

export const translate = (key: string, options?: Record<string, unknown>): string =>
    i18n.t(key, options) as string;

export { i18n };
```

O i18n deve ser importado no `main/index.tsx` **antes** de qualquer componente para garantir que as traduções estejam carregadas:

```typescript
// src/main/index.tsx
import '@/infra/i18n/index.js'; // ← primeiro import
import { App } from '@/main/app.js';
```

## Como adicionar uma nova feature

Adicione as chaves nos dois arquivos JSON com o mesmo caminho:

```json
// pt-br.json
{
    "salesOrders": {
        "title": "Pedidos de Venda",
        "columns": {
            "id": "Nº Pedido",
            "customer": "Cliente",
            "total": "Total",
            "status": "Status"
        },
        "actions": {
            "clone": "Clonar pedido",
            "cloneSuccess": "Pedido clonado com sucesso"
        }
    }
}

// en.json
{
    "salesOrders": {
        "title": "Sales Orders",
        "columns": {
            "id": "Order #",
            "customer": "Customer",
            "total": "Total",
            "status": "Status"
        },
        "actions": {
            "clone": "Clone order",
            "cloneSuccess": "Order cloned successfully"
        }
    }
}
```

## Como usar `translate()` nos componentes

```typescript
// src/presentation/pages/sales-orders/sales-orders-page.tsx

import { translate } from '@/infra/i18n/index.js';

export function SalesOrdersPage({ controller }: Props) {
    return (
        <Box>
            <Typography variant="h5">{translate('salesOrders.title')}</Typography>
            {isLoading && <Loader />}
            {error && <ErrorMessage message={translate('errors.generic')} />}
        </Box>
    );
}
```

## Interpolação de variáveis

```typescript
// Chave com variável: "items": "{{count}} itens encontrados"
translate('salesOrders.items', { count: orders.length })
// → "42 itens encontrados"
```

## Convenções

| Elemento | Convenção | Exemplo |
|---|---|---|
| Arquivos JSON | `kebab-case.json` | `pt-br.json`, `en.json` |
| Chaves | `camelCase` aninhado | `salesOrders.columns.status` |
| Contextos raiz | Nome da feature ou área | `common`, `menu`, `errors`, `salesOrders` |
| Chaves de erro de domínio | Em `errors.*` | `errors.generic`, `errors.notFound` |

## Anti-padrões

❌ **Texto fixo em português no JSX:**
```tsx
<Typography>Pedidos de Venda</Typography> // ← use translate()
```

❌ **Criar chaves apenas em um idioma:**
```json
// pt-br.json tem a chave, en.json não tem
// ← sempre manter os dois arquivos sincronizados
```

❌ **Usar `useTranslation()` do react-i18next em vez de `translate()`:**
```typescript
const { t } = useTranslation(); // ← use a função translate() centralizada
```

## Regras de ouro

1. **`translate()` é a única função de tradução** usada em todo o projeto — não `useTranslation()`.
2. Os dois arquivos JSON (`pt-br.json` e `en.json`) devem ter **exatamente as mesmas chaves**.
3. `@/infra/i18n` é importado **antes de qualquer componente** no `main/index.tsx`.
4. Novos contextos (features) ganham sua própria chave raiz nos JSONs.
5. Mensagens de erro exibidas ao usuário ficam em `errors.*` — mensagens técnicas dos domain errors ficam em inglês.
